# Human Task Request

このドキュメントは、AI が人間に判断・対応を依頼するための **GitHub Issue テンプレート**を定義します。

AI は Human Gate（[HUMAN_GATES.md](./HUMAN_GATES.md)）に該当する状況になったとき、作業を停止し、このテンプレートを使って GitHub Issue を起票します。

---

## Issue 起票方法

```powershell
gh issue create \
  --title "[Human Required] <依頼の概要>" \
  --body "（以下のテンプレートを使用）" \
  --label "human-required"
```

---

## Issue テンプレート

```markdown
## [Human Required] <依頼の概要>

### 背景

<!-- 何のタスクを進めていたか・なぜ人間の判断が必要になったかを説明 -->

- 作業中のタスク: <!-- 例: ai/add-form-validation -->
- 関連 Issue: #<!-- 番号 -->
- 該当する Human Gate: <!-- 例: G8 新しい依存ライブラリ追加 -->

---

### 人間に決めてほしいこと

<!-- 具体的な質問・選択事項を明確に書く -->

1. 
2. 

---

### 選択肢

**選択肢 A:** <!-- 説明 -->
**選択肢 B:** <!-- 説明 -->
**選択肢 C:** <!-- その他 / 方針を変える -->

---

### AI の推奨案

<!-- AI が最も適切だと判断する選択肢とその理由 -->

推奨: 選択肢 __ — 理由: 

---

### リスク

<!-- 各選択肢のリスク・注意事項 -->

- 選択肢 A のリスク: 
- 選択肢 B のリスク: 

---

### 影響範囲

<!-- 変更が影響するファイル・機能・ユーザーの範囲 -->

- 影響ファイル: 
- 影響する機能: 
- ユーザーへの影響: 

---

### 作業を止めている理由

<!-- なぜ人間の確認なしに進められないかを説明 -->

---

### 回答後に AI が再開する手順

人間がこの Issue にコメントで回答後、以下の手順で作業を再開します。

1. Issue のコメントで選択肢を指定してください（例: 「選択肢 A で進めてください」）
2. AI は承認されたブランチに戻り、指定された方針で作業を続けます
3. 作業完了後、通常の WORKFLOW.md のフローに従います

---

### 使用ラベル

<!-- 該当するものにチェック -->

- [ ] `human-required` — 人間の対応が必要
- [ ] `decision-needed` — 方針決定が必要
- [ ] `security-review` — セキュリティ確認が必要
- [ ] `product-decision` — プロダクト判断が必要
- [ ] `design-review` — デザイン確認が必要
```

## 記入例

以下は実際の使用例です。

### 例1: 新しい依存ライブラリ追加が必要な場合

```markdown
## [Human Required] フォームバリデーションライブラリの追加承認

### 背景

- 作業中のタスク: ai/add-form-validation
- 関連 Issue: #12
- 該当する Human Gate: G8 新しい依存ライブラリ追加

入力フォームのバリデーション実装を進めていたところ、
現状の手書きバリデーションでは複雑なルールに対応しにくいため、
ライブラリの追加を検討しています。

### 人間に決めてほしいこと

1. ライブラリを追加してよいか
2. 追加する場合、どのライブラリが適切か

### 選択肢

**選択肢 A:** `zod` を追加（バリデーション + 型推論）
**選択肢 B:** `react-hook-form` を追加（フォーム管理）
**選択肢 C:** ライブラリを追加せず、手書きで対応

### AI の推奨案

推奨: 選択肢 A — `zod` は軽量で TypeScript と相性がよく、
バンドルサイズへの影響も小さいため。

### リスク

- 選択肢 A のリスク: bundle size 増加（約 8kB gzipped）
- 選択肢 B のリスク: bundle size 増加（約 12kB gzipped）、学習コスト
- 選択肢 C のリスク: 複雑なバリデーションルールの保守コスト増

### 影響範囲

- 影響ファイル: `package.json`, `src/App.tsx`
- 影響する機能: Todo 追加フォーム
- ユーザーへの影響: なし（内部実装のみ）

### 作業を止めている理由

`package.json` の変更は Human Gate G9 に該当するため、
人間の承認なしに進められません。

### 回答後に AI が再開する手順

（標準テンプレート通り）
```

---

### 例2: プロダクト方針の確認が必要な場合

```markdown
## [Human Required] Todo の完了後の動作方針を確認

### 背景

- 作業中のタスク: ai/todo-completion-behavior
- 関連 Issue: #7
- 該当する Human Gate: G1 プロダクト方針変更

「完了した Todo の表示」についての仕様が Issue に明記されておらず、
複数の実装方針が考えられるため確認が必要です。

### 人間に決めてほしいこと

1. 完了した Todo はリストに残すか・即時削除するか

### 選択肢

**選択肢 A:** 完了後もリストに残し、打ち消し線で表示する（現状維持）
**選択肢 B:** 完了後に自動でリストから削除する
**選択肢 C:** 「完了済みを隠す / 表示する」トグルを追加する

### AI の推奨案

推奨: 選択肢 A — 既存の実装と一致しており、変更コストが最小。

（以下省略）
```

## ラベル定義

| ラベル | 用途 |
|--------|------|
| `human-required` | 人間の対応が必要な全般的な依頼 |
| `decision-needed` | 方針・設計判断が必要な場合 |
| `security-review` | セキュリティ・認証・個人情報関連 |
| `product-decision` | プロダクト仕様・機能方針の決定 |
| `design-review` | UI/UX デザインの確認・承認 |
