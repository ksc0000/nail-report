# Human Gates

このドキュメントは、AI が自動で進めず **人間の確認・判断を必要とする条件（Human Gates）** を定義します。

AI はこれらのゲートに該当する変更を検出した場合、作業を停止し、[HUMAN_TASK_REQUEST.md](./HUMAN_TASK_REQUEST.md) のテンプレートを使って GitHub Issue を起票してください。

---

## ゲート一覧

| # | ゲート名 | ラベル例 |
|---|---------|---------|
| G1 | プロダクト方針変更 | `product-decision` |
| G2 | UI/UX の大きな変更 | `design-review` |
| G3 | DB スキーマ変更 | `human-required` |
| G4 | 認証・認可変更 | `security-review` |
| G5 | 課金・決済変更 | `human-required`, `product-decision` |
| G6 | 個人情報・セキュリティ関連変更 | `security-review` |
| G7 | 外部 API キーや秘密情報が必要な変更 | `security-review`, `human-required` |
| G8 | 新しい依存ライブラリ追加 | `human-required` |
| G9 | `package.json` 変更 | `human-required` |
| G10 | `.github/workflows` 変更 | `human-required` |
| G11 | Ruleset / CI 変更 | `human-required` |
| G12 | 大規模リファクタ | `decision-needed` |
| G13 | 削除を伴う変更 | `decision-needed` |
| G14 | main へのマージ判断 | ―（PR レビュー） |
| G15 | 本番公開判断 | `human-required` |

## 各ゲートの詳細

---

### G1: プロダクト方針変更

**Trigger:** 機能追加・削除・方向転換・ターゲットユーザー変更など、製品の根幹に影響する判断が必要な場合

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 現状整理・選択肢の列挙・影響範囲の分析 |
| AI がやってはいけないこと | 方針を勝手に決めて実装する |
| 人間に確認すべき内容 | 変更の方向性・優先度・スコープ |
| 推奨ラベル | `product-decision` |

---

### G2: UI/UX の大きな変更

**Trigger:** 画面レイアウトの大幅変更・新規画面追加・ナビゲーション構造変更・デザインシステム変更

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 現状の問題点の指摘・改善案の提示・モックアップ的なコメント |
| AI がやってはいけないこと | 大規模な UI 再設計の実装・既存 UI の全面差し替え |
| 人間に確認すべき内容 | デザイン方針・変更の許容範囲・ユーザー影響 |
| 推奨ラベル | `design-review` |

小さな CSS 調整（余白・色・フォントサイズなど）はゲート不要です。

---

### G3: DB スキーマ変更

**Trigger:** テーブル追加・カラム追加/削除/変更・インデックス変更・マイグレーション

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 変更案の提示・影響範囲の分析・マイグレーションスクリプト案の作成 |
| AI がやってはいけないこと | スキーマ変更の実行・本番データへのアクセス |
| 人間に確認すべき内容 | 変更の後方互換性・ロールバック方法・データ移行方針 |
| 推奨ラベル | `human-required` |

---

### G4: 認証・認可変更

**Trigger:** 認証フロー変更・権限モデル変更・セッション管理変更・ログイン/ログアウト処理変更

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 現状分析・問題点の指摘・改善案の提示 |
| AI がやってはいけないこと | 認証ロジックの単独変更・テストなしのセキュリティ関連実装 |
| 人間に確認すべき内容 | セキュリティ要件・テスト方法・ロールバック手順 |
| 推奨ラベル | `security-review` |

---

### G5: 課金・決済変更

**Trigger:** 課金ロジック変更・決済プロバイダー連携・プラン管理・請求処理

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 実装方針の分析・リスク整理 |
| AI がやってはいけないこと | 課金処理の実装・決済 API の呼び出しコード追加 |
| 人間に確認すべき内容 | 課金仕様・テスト環境の確認・法的要件 |
| 推奨ラベル | `human-required`, `product-decision` |

---

### G6: 個人情報・セキュリティ関連変更

**Trigger:** 個人情報の収集・保存・送信に関わる変更・セキュリティポリシー変更・暗号化変更

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | リスク分析・コードレビュー補助 |
| AI がやってはいけないこと | 個人情報の取り扱いポリシーを単独で決定・実装 |
| 人間に確認すべき内容 | プライバシーポリシーとの整合・法的要件・データの最小化方針 |
| 推奨ラベル | `security-review` |

---

### G7: 外部 API キーや秘密情報が必要な変更

**Trigger:** `.env` ファイルへの追加・Secrets 管理・外部サービス認証情報の取り扱い

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 必要な環境変数のリストアップ・設定方法の説明 |
| AI がやってはいけないこと | 実際の API キーをコードや設定ファイルに書く・Secrets を出力する |
| 人間に確認すべき内容 | キーの取得・GitHub Secrets への登録・ローカル `.env` の設定 |
| 推奨ラベル | `security-review`, `human-required` |

---

### G8: 新しい依存ライブラリ追加

**Trigger:** `npm install <package>` が必要な変更・新規 import の追加

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 候補ライブラリの比較・理由の説明 |
| AI がやってはいけないこと | `npm install` の実行・`package.json` の変更 |
| 人間に確認すべき内容 | ライセンス・セキュリティリスク・バンドルサイズへの影響 |
| 推奨ラベル | `human-required` |

---

### G9: `package.json` 変更

**Trigger:** 依存関係・スクリプト・設定値の変更

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 変更案の提示・理由の説明 |
| AI がやってはいけないこと | `package.json` を直接編集する |
| 人間に確認すべき内容 | 変更の意図・CI への影響・ロックファイルの扱い |
| 推奨ラベル | `human-required` |

---

### G10: `.github/workflows` 変更

**Trigger:** CI/CD ワークフローの追加・変更・削除

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 変更案の提示・問題点の指摘 |
| AI がやってはいけないこと | ワークフローファイルを直接変更する |
| 人間に確認すべき内容 | セキュリティ影響（Secrets の露出など）・トリガー条件・コスト影響 |
| 推奨ラベル | `human-required` |

---

### G11: Ruleset / CI 変更

**Trigger:** Branch Protection Rules・Ruleset・CI ゲートの変更

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 現状分析・変更案の提示 |
| AI がやってはいけないこと | GitHub リポジトリ設定を直接変更する |
| 人間に確認すべき内容 | 保護強度への影響・他の開発者への影響 |
| 推奨ラベル | `human-required` |

---

### G12: 大規模リファクタ

**Trigger:** ファイル構成の大幅変更・アーキテクチャ変更・複数ファイルにわたる構造変更

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 現状の問題整理・リファクタ案の提示 |
| AI がやってはいけないこと | 承認なしに多数のファイルを一度に変更する |
| 人間に確認すべき内容 | 変更スコープの妥当性・段階化の可否 |
| 推奨ラベル | `decision-needed` |

---

### G13: 削除を伴う変更

**Trigger:** ファイル削除・機能削除・コード大量削除

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | 削除候補の整理・影響範囲の分析 |
| AI がやってはいけないこと | 承認なしに既存機能・ファイルを削除する |
| 人間に確認すべき内容 | 削除の必要性・他機能への影響・復旧可否 |
| 推奨ラベル | `decision-needed` |

---

### G14: main へのマージ判断

**Trigger:** PR が CI を通過し、マージ可能な状態になった

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | PR の内容を要約・確認ポイントを提示 |
| AI がやってはいけないこと | `git merge` / PR マージ操作を自動実行する |
| 人間に確認すべき内容 | 差分の最終確認・タイミングの妥当性 |
| 推奨ラベル | ―（PR レビューで対応） |

---

### G15: 本番公開判断

**Trigger:** デプロイ・公開設定・CDN への反映

| 項目 | 内容 |
|------|------|
| AI がやってよいこと | デプロイ手順の確認・チェックリスト提示 |
| AI がやってはいけないこと | 本番環境へのデプロイを自動実行する |
| 人間に確認すべき内容 | リリースタイミング・ロールバック手順・監視設定 |
| 推奨ラベル | `human-required` |

---

## ゲート判断フロー

```text
作業依頼
  ↓
[Human Gate 該当チェック]
  ↓ 該当なし              ↓ 該当あり
通常フロー開始           作業を停止
(WORKFLOW.md)            ↓
                    HUMAN_TASK_REQUEST.md を使って
                    GitHub Issue を起票
                         ↓
                    人間の回答を待つ
                         ↓
                    承認されたら作業再開
```
