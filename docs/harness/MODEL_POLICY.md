# Model Policy

このドキュメントは、AI支援開発における役割ごとのモデル選定方針を定義します。

モデル名は将来の差し替えに備え、**性能ティア**で表現し、具体的なモデル名は参考例として記載します。

---

## 性能ティア定義

| ティア | 説明 | 参考モデル例 |
|--------|------|-------------|
| **High** | 設計・判断・複雑なレビューに必要な高性能モデル | Claude Sonnet / Opus、GPT-4 相当以上 |
| **Mid** | 一般的な実装・単純なレビューに適したモデル | Claude Haiku、GPT-3.5 Turbo 相当以上 |
| **Local** | ローカル実行の軽量モデル（小さい実装・単純修正） | `qwen2.5-coder:7b`、`codellama:7b` 等 |

**原則:**
- 重要判断・設計・セキュリティ・レビューは **High** ティアを優先する
- 小さな実装・単純修正・ドラフト生成には **Local** でも可
- コストと精度のトレードオフを判断するのは人間の責任

---

## 役割別モデル方針

---

### Planner

**役割:** 要件の分解・変更方針の策定・リスク分析

| 項目 | 内容 |
|------|------|
| 推奨ティア | **High** |
| 理由 | 方針の誤りが後工程全体に影響するため、判断精度を優先する |
| Local 可否 | 小規模タスクの初期分解のみ可（必ず人間が確認） |
| 人間判断に戻すタイミング | Human Gates 該当・スコープ不明・要件が矛盾する場合 |

---

### Coder

**役割:** 指定ファイルへの実装・コード変更

| 項目 | 内容 |
|------|------|
| 推奨ティア | **Local** または **Mid** |
| 理由 | Planner の方針が明確であれば、軽量モデルで十分な場合が多い |
| High 必須ケース | セキュリティ関連の実装・複雑なロジック変更・Human Gate 該当タスク |
| Local 可否 | 小さい CSS 調整・単純な UI 変更は可 |
| 人間判断に戻すタイミング | 方針と矛盾する変更が必要と判断した場合・build が通らない場合 |

現在のデフォルト: `ollama/qwen2.5-coder:7b`（Aider 経由）

---

### Reviewer

**役割:** 差分レビュー・品質確認・セキュリティチェック

| 項目 | 内容 |
|------|------|
| 推奨ティア | **High** |
| 理由 | 見落としリスクが高く、精度が求められる |
| Local 可否 | 単純な形式チェック（CSS guard 等）は自動化・スクリプトで代替 |
| 人間判断に戻すタイミング | NG 判定・判断が難しいトレードオフ・セキュリティ懸念 |

---

### Tester

**役割:** build 確認・手動確認項目の実行

| 項目 | 内容 |
|------|------|
| 推奨ティア | **Mid** または **Local** |
| 理由 | `npm run build` 等のコマンド実行と出力の確認が主な役割 |
| High 必須ケース | E2E テスト設計・テスト戦略策定 |
| 人間判断に戻すタイミング | build 失敗・手動確認で問題発見 |

---

### Release Manager

**役割:** commit 整理・PR 作成補助・merge 前最終確認

| 項目 | 内容 |
|------|------|
| 推奨ティア | **Mid** または **High** |
| 理由 | commit message の品質・merge 可否の最終判断を補助する |
| Local 可否 | 機械的なチェックリスト確認は可 |
| 人間判断に戻すタイミング | merge 判断は常に人間に戻す（G14） |

---

### Security Reviewer

**役割:** セキュリティ観点での差分レビュー・脆弱性チェック

| 項目 | 内容 |
|------|------|
| 推奨ティア | **High** 必須 |
| 理由 | セキュリティの見落としは直接的なリスクにつながる |
| Local 可否 | 不可 |
| 人間判断に戻すタイミング | 常に人間への報告が必要（G4/G6 参照） |

---

### UI/UX Reviewer

**役割:** 画面デザイン・UX の確認・改善提案

| 項目 | 内容 |
|------|------|
| 推奨ティア | **High** または **Mid** |
| 理由 | ユーザー体験の評価には文脈理解が必要 |
| Local 可否 | 細かい CSS 調整の確認は可 |
| 人間判断に戻すタイミング | 大きな UI 変更の方向性（G2 参照） |

---

## モデル選定フロー

```text
タスクを受け取る
  ↓
Human Gate 確認（HUMAN_GATES.md）
  ↓ 該当あり                   ↓ 該当なし
Human Gate 処理               タスク規模を判断
                                ↓ 大 / セキュリティ関連
                             High ティアを選択
                                ↓ 小 / 単純実装
                             Local または Mid を選択
                                ↓
                             実行
                                ↓
                             Reviewer（High）で確認
                                ↓
                             人間レビュー → commit
```

---

## `qwen2.5-coder:7b` の位置づけ

このリポジトリでは Aider + Ollama による `qwen2.5-coder:7b` を軽量ローカル実装担当として採用しています。

**向いている作業:**
- 小さな CSS 調整
- 既存パターンに沿ったコンポーネント修正
- シンプルな UI テキスト変更

**向いていない作業:**
- セキュリティ関連の実装
- 複雑なロジック変更
- アーキテクチャ判断
- 大規模な機能追加

ローカルモデルの出力は必ず人間が `review-ai-diff.ps1` で確認してください。

---

## モデルの差し替えについて

モデル名はこのドキュメントでは固定しません。  
以下の条件が揃えば、同ティア内でモデルを差し替えることができます。

- 同等以上の性能ティアであること
- AGENTS.md の Aider 起動コマンドを更新すること（人間の承認が必要）
- `package.json` を変更しないこと
