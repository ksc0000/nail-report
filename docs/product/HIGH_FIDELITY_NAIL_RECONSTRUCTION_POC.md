# High-Fidelity Nail Reconstruction PoC — 設計書(調査・設計フェーズ / 実装前)

> **ステアリング(2026-10-11 オーナー承認)**: 最優先目標は「実際に施術したネイル 1 本を、本人が納得できる忠実度で 3D 復元すること」。

### 0.1 研究の手間と製品の撮影体験は別物(2026-10-13 オーナー確認)

- **製品の撮影体験の目標**: 手を置いて(または空中で静止させて)、スマホで周りを**約 90° ぐるっと数往復**撮るだけで爪のモデルが登録される。
  往復回数は固定しない(1・2・3 往復で品質と撮影時間の関係を測ってから決める。§4.2)。
  ユーザーに課すルールは **「撮影中は手を動かさない」1 つだけ**を目標とする(E0 では、カメラを固定して手を回す撮り方は今回の SfM 条件で位置推定が成立しなかった。§4.1)。
- **研究だけの手間**(評価用 hold-out・ノギス実測・パイロット・条件比較)は「どこまで忠実か」を測るためのもので、**ユーザーには課さない**。
  露出・ホワイトバランスの固定や高解像度静止画の取得は、製品ではアプリが自動で行う前提とする。
- **完全な形状復元を絶対としない**: 最終方式は「ユーザーが必要とする忠実度」×「技術的に届く忠実度」で決める。
  形状は用意済みのモデル(パラメトリック形状ライブラリ)に寄せ、見た目(柄・ラメ・質感)だけを撮影から取る**ハイブリッド方式**(§2 の H1・H2)を正式な比較対象に含める。
  本 PoC で優先するのは **H1(パラメトリック形状＋UV テクスチャ投影)**。
  どこまでの曲がり具合・形状精度が求められるかは、推測せず §5.1 の要件確認で決める。

## 2. 復元方式の比較(A / B / C / M ＋ ハイブリッド H1・H2)

| 軸 | **A: 複数写真+パラメトリック** | **B: 動画・多視点+幾何復元** | **C: 多視点外観再構成(3DGS 等)** | **M: 手動補正付き復元(基準)** |
|---|---|---|---|---|
| 中身 | 既存路線: AngleStep 撮影 → shape/curve 推定 → パラメトリック板 + テクスチャ投影(**要新規実装**) + 合成質感 | SfM/MVS or Apple PhotogrammetrySession(**Mac 上**)で実測メッシュ+テクスチャ | 40〜80 視点から 3D Gaussian Splatting を学習(Mac 上)。視点依存の輝きをそのまま持つ | A の出力を tune sheet + 必要なら Blender で人手調整 |
| 形状忠実度 | 中(5 shape テンプレの範囲。outline 未使用・自由形状不可) | **高**(実測。装飾パーツの立体も写る) | 中〜高(メッシュではないが輪郭・凹凸の見えは正確) | 中(人の目で合わせた分だけ) |
| デザイン(柄) | 中(投影実装後)。現状は crop 貼りで低 | 高 | **高** | A に準ずる |
| 質感(ラメ・マグネット・オーロラ) | **低〜中**(合成フレック。実物の輝きは再現しない) | 低(拡散テクスチャに焼き付く。視点依存は失われる) | **最高**(視点依存がそのまま再現。マグネットジェルの「動く」質感はこれだけが表現可能) | A に準ずる |
| 装飾(ストーン・パーツ) | 不可(契約にも表現がない) | **高**(形状が実測される) | 高(見えとして) | 形状は不可、見えのみ手調整 |
| 再現性(撮り直して同じか) | 高(パラメータ空間が狭い) | 中(撮影条件に敏感: 光沢面で特徴点が壊れる) | 中(学習のゆらぎ・撮影依存) | 人依存 |
| オンデバイス可否(製品化時) | **可**(現行実装の延長) | △(iOS Object Capture は小さく光沢のある爪に不向きと既評価。Mac なら可) | △(学習は現状 Mac/サーバー級。描画はモバイル可) | 可 |
| CND 整合 | **ネイティブ**(canonical そのもの) | 派生アセット(メッシュ)。パラメータ+heightMap/normalMap への蒸留で契約内に還元可能 | 派生アセット(新種別)。canonical にはならない | ネイティブ |
| 記録フローの重さ | 軽(現状並み) | 重(数十枚・撮影規律) | 重(同上+学習待ち) | 最重(人手) |
| PoC 実施コスト | 小〜中(投影の実装が主) | 小(既製ツールを Mac で回すだけ) | 小〜中(nerfstudio/gsplat 系既製ツール) | 小 |

**ハイブリッド方式(2026-10-13 追加・レビューで H1/H2 に分離)** — 形状は A の用意済みモデル(5 shape＋curveV/H、iOS/Web に実装済み)から選ぶか少数パラメータで合わせ、
見た目は撮影から取る。見た目の持たせ方で 2 つに分ける。

| | **H1: パラメトリック形状＋UV テクスチャ投影(優先)** | **H2: パラメトリック形状＋視点依存の外観表現(別研究)** |
|---|---|---|
| 見た目の持たせ方 | 撮影画像を爪の板の UV 空間へ投影した 1 枚のテクスチャ(＋既存の合成質感) | 見る角度で変わる輝き(ラメ・マグネット)を爪の板の表面に持たせる |
| 実現性 | 高い。P2(A のテクスチャ投影)の成果をそのまま使える。CND 契約の `NailTexture` にそのまま載る | **未確立**。3DGS はシーン全体を点の集まりとして表すので、学習結果を爪の板へ単純に貼り付けても成立しない。表面上の視点依存表現(例: 板に沿った splat の拘束、ニューラルテクスチャ)を新たに研究する必要がある |
| 形状の忠実度 | A 相当 | A 相当 |
| 柄 / 質感の忠実度 | 柄は B/C 相当を狙える。視点で変わる輝きは再現しない | 柄・輝きとも C 相当を狙える(実現できた場合) |
| 本 PoC での扱い | **比較対象(PH ステップ)。B/C の完全な形状復元が難しい場合、またはユーザーが形状の細部をそれほど求めない場合(§5.1)の第一候補** | **本 PoC の比較には含めない。** H1 と C の結果から「視点で変わる輝きが納得に必要か」が分かった場合に、別の研究課題として起票を提案する |

**各方式の既知リスク**
- A: 忠実度の天井が構造的に低い(テンプレ形状・合成質感・装飾なし)。本 PoC の問いは「投影を実装した A はどこまで『納得』に届くか」。
- B: ジェルの鏡面反射が SfM/MVS の特徴点マッチングを壊す定番条件。拡散光・偏光などの撮影規律で緩和できるかが論点。小物体(10〜18mm)のスケール校正も必要(実測値を併記)。
- C: 製品化時にプライバシー原則(生フレーム端末外不可)と衝突する(PoC はオーナー Mac 上で学習するため抵触しない)。canonical になれないため「忠実度は C、記録の正は A/CND」というハイブリッドが着地点になり得る。
- M: 自動化の答えではないが、「本人の納得」の天井と、納得を支配する軸(形状か質感か)を最小コストで特定できる。
  **注意(スコープ限定)**: M は A と同じパラメトリック表現を人手で調整するものなので、M の品質天井が縛るのは**同じ表現系の A だけ**である。
  B(実測メッシュ)と C(視点依存外観)は M より表現力の高い別系であり、**M で届かない品質に B/C が届くことは十分あり得る**。
  M の役割は (1) パラメトリック表現系の上限測定、(2) 納得を支配する軸の特定、の 2 点に限る。

### 3.1 HF-4(方式 C)の実行環境 — 事前調査(2026-10-12)

## 4. 必要な撮影データ(オーナー作業・1 セッション)

被写体: **右手親指**(オーナー選定、紫のラメジェル)。

### 4.1 E0 パイロットの結果(2026-10-12 実施済み・データは `~/hf1-pilot/` に隔離、入力にも hold-out にも使わない)

**注意: ここで測ったのは COLMAP の画像登録(カメラ位置が求まったか)だけで、ネイルの復元品質ではない。** E0 では 3DGS の学習も
復元品質の評価も行っていない。登録できたことは復元の前提条件にすぎず、爪の形や見た目がどこまで忠実に復元できるかは本撮影後の評価(§5)で測る。

| 試験 | COLMAP の画像登録(位置が求まった枚数) | 爪の画質の目視確認(登録とは別) |
|---|---|---|
| 静止画 5 枚(約 30° 刻み)、黒マット | **0/5**(初期ペアが作れない。ラメは視点で見え方が変わり一致しにくい) | 良好(ラメの粒まで鮮明) |
| 回り込み動画、黒マット | **70/70**(約 85°、1 フレーム約 1.3°) | 甘い(手全体の構図で爪は幅約 250px、動きブレと圧縮) |
| 動画＋手全体の静止画 5 枚、黒マット | **91/92**(縦・横の静止画は別カメラとして扱う必要あり) | 静止画は良好、爪は幅約 250px |
| 動画＋親指の接写 3 枚、白い無地ボード | 動画 90/90、接写 **2/3**(失敗した 1 枚は親指と白い面しか写っていない) | 接写は良好(爪の画素数が数倍)。背景の色で爪の色が暗く写った |
| カメラ固定・手を回す動画(iPad Air M4) | **0/86**(475 組中 474 組が「カメラが動いていない」と判定) | — |

手を回す方式の 0/86 は、**今回の SfM 条件(COLMAP の標準設定で、背景も含めたシーン全体を 1 つの剛体として扱う)では成立しなかった**、という結果である。
技術的に不可能という意味ではない。たとえば背景をマスクして手だけを対象にする、手の動きを別途追跡する、といった条件では成立する可能性があり、本 PoC では検証していない。

E0 から決まった撮影ルール(今回の条件での推奨): 手は動かさずカメラを動かす / 位置推定は動画、細部は静止画 / 接写には必ず目印(隣の指の付け根・マットの縁)を入れる /
背景の色で爪の色が変わるため露出を固定し、色の基準(白い紙片かグレーカード)を写し込む / 撮影者の影を爪に落とさない拡散光 /
カメラの位置情報はオフ(取り込み時にも GPS を除去する)。

### 4.2 本撮影のセット(製品と同じ撮り方を主軸にする)

| セット | 内容 | 用途 | ユーザーにも課すか |
|---|---|---|---|
| **E1(評価用・最初に撮る)** | 決めた 8〜12 方向の静止画+**実測**(爪の幅・長さをノギス等で mm 計測)+点光源下で指をゆっくり回す 10 秒動画(質感の正解) | **hold-out。どの方式の入力にも使わない** | 課さない(研究のみ) |
| **R-main(主軸)** | **製品と同じ撮り方**: 手を置いたまま、約 90° を 3 往復。1 往復目は手全体、2 往復目は少し近く、3 往復目は親指の近くで、往復ごとに別の動画として撮る(各 20 秒程度)。3 往復目の途中で 2× の静止画を数枚 | 全方式の入力(主要評価)。往復ごとに分けて撮るので、1・2・3 往復の比較にもそのまま使う(§4.3) | **製品の撮影体験の候補**(往復回数は §4.3 の結果で決める) |
| R-max(上限比較) | R-main に加えて、目印入りの接写と中くらいの距離のショットを追加した最大限の撮影 | 「手間をかければどこまで上がるか」の比較 | 課さない(研究のみ) |
| R1 | 既存 AngleStep の 4 方向ガイド撮影 1 セット | 方式 A / M / H1 の入力 | 既存の製品フロー |
| R3(再現性用) | 手を置き直して R-main をもう 1 回 | 再現性評価 | — |
| R-air(任意) | 手を空中で静止させて R-main と同じ撮り方 | 空中撮影が成り立つか(手の小さな揺れが位置推定を壊すかの確認) | 結果次第で製品に採用 |

**主要な問い**: R-main(手軽な撮り方)と R-max(最大限の撮り方)の忠実度の差。差が小さければ、手軽な撮り方のまま製品化を目指せる。

**R-main と R-max の比較の公平性**: 違いは**撮影データだけ**にする。

- 両者に**同じ復元アルゴリズムと同じ設定**を使う(COLMAP の設定、フレーム抽出のレート、3DGS の学習 step 数・学習率・splat 数の上限、乱数シード)。
  R-max は画像が多いので、step 数を固定すると 1 枚あたりの学習量が減る。そのため**「step 数固定」と「収束まで(評価値が頭打ちになるまで)」の 2 条件で両方を学習**し、
  どちらの条件でも差が同じ向きかを確認する。学習条件の違いによる差を、撮影データの差と混同しない。
- **評価は同じ E1 hold-out・同じ指標・同じレンダリング設定**で行う。本人評価も同じセッション内で、どちらの撮影か伏せて提示する。
- 3DGS は乱数で結果が揺れるので、各条件を**シードを変えて 3 回**学習し、ばらつきの範囲を差と並べて報告する。

### 4.3 撮影時間と品質の関係(往復回数の最適化)

3 往復を製品の必須条件として固定しない。R-main を往復ごとに別の動画として撮り、次の組み合わせで復元して比べる。

| 条件 | 使う動画 | 測るもの |
|---|---|---|
| 1 往復 | 1 往復目のみ(手全体)/ 3 往復目のみ(近く)の 2 通り | 画像登録率・復元品質(§5)・撮影時間 |
| 2 往復 | 1＋3 往復目 / 1＋2 往復目 | 同上 |
| 3 往復 | すべて | 同上 |

- 復元アルゴリズム・学習条件・評価条件は §4.2 の公平性ルールと同じにそろえる。
- 撮影時間は動画の長さの合計に加えて、往復の切り替えにかかった時間も記録する(EXIF の撮影時刻から算出)。
- 結果は「品質 対 撮影時間」の表にまとめ、本人評価が 4/5 に届く最短の撮り方を製品の撮影条件の候補にする。

プライバシー: 爪のクローズアップ中心、顔・個人特定物を写さない。EXIF 位置情報なし。データはオーナーの端末と Mac 内のみ、リポジトリには数値・メッシュ・レポートのみ(10A と同じ `data/.gitignore` 方式)。

## 5. 品質評価方法

原則: **全評価は実写(E1 hold-out)との比較**。合成データでの合格判定はしない。

| 軸 | 定量 | 定性(本人) |
|---|---|---|
| 形状 | E1 各視点でのシルエット IoU / 輪郭距離。実測 mm との寸法誤差 | 「自分の爪の形か」1〜5 |
| デザイン(柄) | E1 視点でレンダリングと実写の爪領域 SSIM/LPIPS | 「柄が合っているか」1〜5 |
| 質感 | E1 の回転動画と各方式の回転レンダリングを並べて A/B | 「輝き・質感が本物か」1〜5 |
| 装飾 | 斜め視点のシルエットにパーツの出っ張りが出るか | 「パーツが再現されているか」1〜5 |
| 再現性 | R3 再構成との幾何差(10A の M 系指標を流用)・見た目差 | 「2 回で同じに見えるか」 |

**主要判定 = 本人評価**: 各軸 4/5 以上を「納得」とする(ステアリングの定義どおり、数値は補助)。評価セッションは方式名を伏せてランダム順で提示(10A のブラインド手法を流用)。

### 5.1 要件確認 — ユーザーはどこまでの忠実度を求めるか(2026-10-13 追加)

「正確な曲がり具合が必要か」は推測で決めず、比較で確かめる。

2 つのテストに分ける。混ぜると「形の違い」と「見た目の違い」のどちらに反応したのか区別できなくなるため。

**(a) 形状知覚テスト(形状パラメータだけを変える)**

- **固定するもの**: 柄(同じ UV テクスチャ 1 枚、H1 の投影結果)・質感(同じマテリアル設定)・照明(同じ環境光とライト配置)・カメラ(同じ視点と画角)・レンダラー(同じビューア)。
- **変えるもの**: 形状パラメータ(shape・curveV・curveH・length・thickness)**だけ**。基準の形状から 1 つずつ段階的にずらした版を作る。
- **測るもの**: どの程度ずらすと本人が「違う」と気づくか(既存の知覚しきい値実験 `/nail3d-calibration` と同じ考え方。順番はランダム、どれが基準かは伏せる)。
- **基準の形状の扱い**: B/C の結果を**無条件に幾何形状の正解とはみなさない**(光沢面では SfM/MVS の形状がゆがみやすく、3DGS はそもそも面の形状を直接持たない)。
  基準は E1 の実測(ノギスの mm 値)と E1 hold-out 写真のシルエットに最もよく合うパラメータとし、B/C の形状はその候補の 1 つとして同じ基準で採点する。

**(b) 総合比較(方式ごとの見た目の納得度)**

- **比較する組み合わせ**: (1) B/C の撮影から取った形状＋見た目、(2) H1: 用意済みの形状＋UV テクスチャ投影、(3) 用意済みの形状＋合成の質感(現行 iOS 相当)。
- **問い**: 「自分の爪に見えるか」「柄と質感の再現は足りているか」を、方式名を伏せて提示する。

**共通**

- **対象**: まずオーナー本人。他のユーザーに見てもらう場合は、オーナーの同意を得てレンダリング画像のみを使う(元写真は見せない)。
- **使い方**: (a) で形状の差に気づかない範囲が広く、(b) で H1 が 4/5 に届けば、H1 を第一候補にして形状の完全復元に投資しない。
  (a) で小さな形状差にも気づく場合だけ、B/C の形状復元(またはパラメトリック形状の精密化)を製品化の対象にする。
