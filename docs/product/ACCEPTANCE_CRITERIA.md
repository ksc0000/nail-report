# Acceptance Criteria

このドキュメントは、AI が「タスク完了」と判断するための基準を定義します。

AI はタスクを完了する前に、該当するセクションのチェックリストを全て確認してください。  
1つでも未達成の項目があれば、そのタスクは **未完了** です。

---

## 1. 全タスク共通の完了条件

どのタスクでも必ず確認します。

```text
[ ] git status が clean か、変更ファイルが意図したもののみである
[ ] 変更対象外ファイルが変更されていない
[ ] package.json が変更されていない
[ ] package-lock.json が変更されていない
[ ] src/main.tsx が変更されていない
[ ] npm run build が成功している（エラーなし）
[ ] TypeScript の型エラーが残っていない
[ ] 既存の NailItem 機能（追加・編集・削除・画像アップロード）が壊れていない
[ ] Reviewer Agent のチェックを通過している（判定: OK）
```

---

## 2. ドキュメント変更の完了条件

`docs/` や `.md` ファイルを変更するタスクに適用します。

```text
[ ] 文章として読めるか（Markdown 構文が正しいか）
[ ] リンクが正しく機能するか（相対パスの確認）
[ ] 既存ドキュメントと矛盾する記述がないか
[ ] AGENTS.md / CONVENTIONS.md と整合しているか
[ ] 全タスク共通の完了条件を満たしている
```

---

## 3. UI 変更の完了条件

`src/App.tsx` や `src/App.css` を変更するタスクに適用します。

```text
[ ] CSS guard（check-css-guard.ps1）が passed である
[ ] npm run build が成功している
[ ] 以下の手動確認項目を全て通過している:
    [ ] 画面が表示される（ログイン前・ログイン後）
    [ ] ログイン / ログアウトができる
    [ ] ネイルアイテムを追加できる（タイトル必須・タグ・メモ・画像）
    [ ] ネイルアイテムを編集できる
    [ ] 削除確認ダイアログが表示され、OK で削除できる
    [ ] 検索ボックスでタイトル・タグ絞り込みができる
    [ ] 新着順（updatedAt 降順）でリストが表示される
    [ ] 画面が崩れていない（デスクトップ幅・モバイル幅）
[ ] App.tsx に createRoot が混入していない
[ ] App.tsx に StrictMode の root rendering が混入していない
[ ] CSS に ${...} のような JavaScript 式が混入していない
[ ] 全タスク共通の完了条件を満たしている
```

---

## 4. ロジック変更の完了条件

ビジネスロジック・state 管理・イベントハンドラを変更するタスクに適用します。

```text
[ ] 変更した機能が仕様通りに動作する
[ ] 既存機能を壊していない
[ ] 型エラーがない（TypeScript）
[ ] エラーハンドリングが適切である（必要な場合）
[ ] 意図しない副作用がない（他の state への影響等）
[ ] 全タスク共通の完了条件を満たしている
```

---

## 5. 依存関係変更の完了条件

> **注意:** `package.json` の変更は Human Gate G9 に該当します。  
> 人間の承認なしにこの作業を完了してはいけません。

```text
[ ] 人間による承認が完了している（Human Gate G9）
[ ] ライセンスが問題ないことを確認している
[ ] セキュリティリスクを確認している
[ ] bundle size への影響を確認している
[ ] npm ci が成功する
[ ] npm run build が成功する
[ ] 全タスク共通の完了条件を満たしている
```

---

## 6. セキュリティ関連変更の完了条件

認証・認可・個人情報・API キー・セキュリティポリシーに関わるタスクに適用します。

> **注意:** セキュリティ関連の変更は Human Gate G4 / G6 / G7 に該当します。  
> 人間の承認と Security Reviewer のレビューが必要です。

```text
[ ] 人間による承認が完了している（該当する Human Gate 番号: __ ）
[ ] Security Reviewer（High ティアモデル）のレビューが完了している
[ ] API キー・秘密情報がコードに含まれていない
[ ] 環境変数が適切に管理されている（.env が .gitignore に含まれている）
[ ] 認証情報がログに出力されていない
[ ] 全タスク共通の完了条件を満たしている
```

---

## 7. PR 前チェックリスト

`git push` して PR を作成する前に確認します。

```text
[ ] 全タスク共通の完了条件を満たしている
[ ] 該当するタスク種別の完了条件を満たしている
[ ] review-ai-diff.ps1 を実行し、結果を確認した
[ ] git --no-pager diff を人間が確認した
[ ] commit message が規約に従っている（feat/fix/style/refactor/docs/chore:）
[ ] ブランチ名が命名規則に従っている（ai/ chore/ docs/ fix/）
[ ] 不要なデバッグコードが残っていない
[ ] console.log が残っていない（デバッグ用のもの）
[ ] TODO コメント / FIXME コメントが残っていない（意図的なものを除く）
```

---

## 8. マージ前チェックリスト

PR が作成されてから main へマージする前に確認します。

> **注意:** マージは必ず人間が判断・実行します（Human Gate G14）。

```text
[ ] GitHub Actions CI が全て green（CSS guard + build）
[ ] Branch Ruleset を通過している
[ ] PR の diff を人間がレビューしている
[ ] 関連 Issue がクローズ可能な状態になっている
[ ] 必要な場合、他の PR との依存関係が解決されている
[ ] マージ後に動作確認する手順が明確になっている
```

---

## Reviewer Agent が使う判定フォーマット

Reviewer Agent はこの基準に基づいて以下の形式で判定を出します。

```text
判定: OK / NG
変更ファイル:
良い点:
問題点:
修正必須:
commit 可否:
```

**NG 条件（即座に作業停止）:**

- build 失敗
- 指定外ファイル変更
- `package.json` 変更
- `src/main.tsx` 変更
- `App.tsx` に root rendering 混入
- CSS に JavaScript 式混入
- 既存機能（NailItem CRUD）の削除
- TypeScript 型エラー残存
