# Nailous — 年内 App Store リリース ロードマップ(2026-11-07 起草)

> **ゴール**: 2026-12-31 までに Nailous iOS を App Store で公開する。
> **v1.0 の看板機能**: **ライブ試着** — カメラに手をかざすと、5 本の指先に選んだネイルセット(色・仕上げ・形)が**自動で**乗る。写真を選んで手で置く方式(PR 相当の `PhotoTryOnView` 試作、2026-11-07 にオーナーが「期待外れ」と判定)は採用しない。
> **不変の原則**: L0 の写真記録は常に成立する(試着が失敗しても記録は壊れない)。写真・映像は端末外に出さない。

関連: #404(Epic)/ #425(UI 仕様)/ #424(商用 MVP ゲート)/ #430(爪領域の取得)/ #431(試着)/ `IOS_RELEASE_PATH_DECISION.md`(旧: PWA 優先 — #404 の G1 でネイティブ iOS + App Store が承認済みのため、本書が優先)

## 0. 残り日数と、それが決める方針

今日から 12/31 まで **7 週と 4 日**。Apple の審査は通常 1〜3 日だが、12 月後半は混み、差し戻しが 1 回あると 1 週間消える。したがって:

- **提出目標 12/12(金)**、遅くとも **12/19(金)**。12/20 以降の提出は「年内」を保証できない。
- 新規の機械学習モデルの学習(爪の輪郭セグメンテーション)は **v1.0 に入れない**。ライブ試着は Vision の手のランドマーク(指先・第一関節)だけで位置・角度・大きさを決める。輪郭に沿った精密な重ね合わせは v1.1(#430 の段階 2〜3)。
- 3D 復元(HF-PoC #416)・CND 契約の変更・クラウド処理は **v1.0 の対象外**。研究は続けるがリリースのクリティカルパスから外す。

## 2. ライブ試着の技術方針(最短で成立する形)

既存資産に足すのは「動画フレームの経路」と「フレーム間の安定化」だけ。

```
AVCaptureVideoDataOutput(30fps, 720p〜1080p)
  → VNDetectHumanHandPoseRequest(フレームごと、既存 NailDetector の設定を流用)
  → 指ごとに TIP / DIP ランドマーク → 位置 = TIP から DIP 方向へ少し戻した点(既存の 0.32 補間)
                                   角度 = DIP→TIP ベクトル、大きさ = |TIP−DIP| × 形状ごとの係数
  → One-Euro フィルタで位置・角度・大きさを平滑化(ジッタ対策)
  → 5 本分の NailSilhouette を色・仕上げ(既存の合成質感)で描画してプレビューに重ねる
```

- **既知の限界(承知のうえで出す)**: 爪の輪郭にぴったりは沿わない(ランドマークは関節位置であって爪の縁ではない)。指が重なる・曲がると追従が乱れる。ラメ・マグネットの本物の輝きは再現しない(合成)。→ ストアの説明文とアプリ内の文言で「色味と形のイメージ確認」と明示する。
- **性能の目安**: iOS 17 対応機(A12 以降)でランドマーク推定は 1 フレーム 10〜20 ms。描画込みで 30fps を目標、落ちる端末では 15fps に自動で下げる。
- **Go / No-Go(W1 末, 11/14)**: 実機で「手をかざして 1 秒以内に 5 本が乗り、ゆっくり動かしても外れない」なら GO。外れが多ければ、v1.0 は「ライブ試着(β)」の表記で出すか、静止画 1 枚にランドマークで自動配置する方式に縮退するかをオーナーが判断。

## 4. 今すぐ必要なオーナー判断(W1 に入る前)

1. **Apple Developer Program(有料)と App Store Connect のアプリ登録**の有無。未登録なら W1 中に登録(承認に 1〜2 日)。Bundle ID は `com.ksc0000.nailous` のまま。
2. **v1.0 のスコープ承認**(§1)。特に `AICleanup`(Replicate 送信)の無効化と、3D 復元をリリース対象外にすること。
3. **ライブ試着の品質基準**(§2 の Go/No-Go)をこの文面で受け入れるか。
4. **TestFlight の外部テスター**を誰にするか(5〜10 人。#424 の利用者・ネイリスト面談と兼ねる)。
5. **コードの置き場**: iOS ソースは `nailous-loop-work` 系にしかなく、`main` には Swift ファイルがない。リリースまでは `release/1.0` ブランチを `nailous-loop-work` から切って作業し、`main` との統合は公開後に判断(今やると統合作業が W1 を食う)。

## 5. 主なリスクと手当て

| リスク | 手当て |
|---|---|
| ランドマーク方式の追従が粗く「乗っている感」が弱い | W1 の Go/No-Go で早く見極める。縮退案(静止画への自動配置)を W2 の予備に持つ |
| 審査差し戻し(カメラ用途、写真ライブラリ用途、デモ不足) | 用途文言を具体的に書く、審査メモにデモ動画、テストアカウント不要の構成 |
| 旧機種で発熱・フレーム落ち | 解像度 720p、15fps への自動降格、5 秒以上の連続推論で解像度を落とす |
| 12 月後半の審査遅延 | 12/12 提出。12/19 を最終期限とし、超えたら「年内」を年明けに切り替える判断を事前に合意 |
| 研究トラックと取り合いになる | リリース期間中は研究のオーナー作業(撮影・評価)を W6 以降に寄せる |
